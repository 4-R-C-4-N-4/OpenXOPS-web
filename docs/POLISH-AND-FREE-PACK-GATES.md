## Small milestones and acceptance commands

1. **Pack inventory/provenance (now):** `python3 tools/validate_pack.py assets/pack`; `python3 -m unittest discover -s tools/tests -p 'test_*.py' -v`; `python3 tools/sfxgen/analyze.py check assets/pack/data/sound/*.wav`. Baseline: 66 P0 failures, tests pass, SFX pass. Every next asset needs original authorship or explicit free source, SHA-256 and license record; human curation recorded separately.
2. **One authored map/mission:** create only needed clean-room `.bd1`/tiles, `.pd1` and mission metadata; validate binary counts/texture names and CP932. Ensure tile files are actually referenced by the map (avoid unlisted paths). Do not reuse original maps/layouts/screenshots.
3. **Minimum render/load set:** author minimal model/skin/weapon and HUD/font assets according to `docs/ASSET-CONTRACT.md`; run pack validator and model checker (`python3 tools/contract/check_x.py ...` for each `.x`), inspect DDS/BMP headers, provenance and clean-room guard. Decide and test which unconditional resources are required by the actual loader.
4. **No-upload playable proof:** build packaged web release, serve the artifact, start with no selected ZIP, complete one mission route (briefing → gameplay → fire/hit → result), capture console and inspect render. Keep captured evidence out of the repo if derived from original data. A passing validator alone is not playable proof.
5. **Release regression:** rerun validator/tests and browser error/cache/settings checks; assert zero P0 failures, no unlicensed assets, all shipped files hash-provenanced, and no QA exports/original archive in staged artifact.
